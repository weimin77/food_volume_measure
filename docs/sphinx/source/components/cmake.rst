CMake targets
=============

``CMakeLists.txt`` reads the package name, language standards, and build switches from
``metadata.json``. It collects public headers from ``include/`` and implementation files
from ``src/``. The scan is scoped to those directories, so tests and examples do not become
library sources.

Targets installed for consumers
-------------------------------

The regular build creates ``food_volume_measure_c`` and ``food_volume_measure_cpp`` plus an
interface target, ``food_volume_measure``, that links both. The current project has no C
implementation files; the C target is kept for the template's C/C++ package layout. The
measurement API is C++ and lives in ``measurement.hpp`` and ``types.hpp``.

An installed consumer can use the exported target:

.. code-block:: cmake

   find_package(food_volume_measure CONFIG REQUIRED)
   target_link_libraries(my_app PRIVATE food_volume_measure::food_volume_measure)

The Conan toolchain supplies the dependency locations. The CMake configuration expects
``C_DEPS`` and ``CPP_DEPS`` in the ``Pkg@Target`` form generated by the recipe; invoking the
root CMake project without that setup requires providing equivalent dependency settings.

Optional outputs
----------------

The default C++ standard is 17. C++ module compilation is considered only with C++23 or
newer. A host build with ``enable_python_bindings`` enabled also installs the
``food_volume_measure_python`` module; a cross build skips it. On Windows, a requested
shared-library build falls back to static with a warning. See :doc:`project metadata <meta>`
for the switches that control these choices.
